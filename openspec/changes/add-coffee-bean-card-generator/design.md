## Context

当前 Vue 应用是本地 A4 九宫格图片排版器，使用 Pinia 保存编辑状态、Canvas 绘制 PNG。新工作流新增独立页面，用于录入咖啡豆资料并制作单张豆卡；原九宫格页面和行为保持不变。参考图定义了两种白底模板：1:1 正方形和 A4 直式。`src/assets/fonts/Libian.ttc` 是必须使用的繁体中文字体资源。

卡片预览、插图与导出在浏览器内完成。豆子资料通过同项目的 Express 服务读取并写回 `src/public/beans-data.json`；首版不引入账号或云端数据库。

## Goals / Non-Goals

**Goals:**

- 以精确、可配置的模板坐标复刻参考图的文字层级、留白与配色。
- 通过同一份画布场景数据驱动屏幕预览和高分辨率 PNG，避免预览与下载不一致。
- 让两种模板都能本地导入多张插图，并提供直接操控的拖拽、缩放、层级与删除能力。
- 在预览和导出中嵌入加载后的 Libian 字体，保证繁体文本一致。
- 让用户能从原九宫格页面进入豆卡页面，并能返回原工具，且两者编辑状态互不干扰。
- 支持在页面选择、创建、修改与删除可持久化的豆子资料。

**Non-Goals:**

- 不提供 AI 图像生成、多人协作、账号或模板在线管理。
- 不提供任意自定义文字样式和任意新建模板；首版只包含两份参考模板。
- 不改变既有九宫格图片拼版、页面边距、图片间距或其导出行为。

## Decisions

### 使用模板定义而非 DOM 截图导出

每个模板定义画布比例、归一化文字锚点、字号、行距、颜色与插图可用区域。编辑预览和导出均调用相同 Canvas 场景渲染器：预览按容器缩放，下载按目标分辨率渲染。

竖版模板按 827×1169 单元格使用参考图的紧凑坐标：标题基线约 y=520、字段从 y=650 开始（38 px 字号）、店铺名称基线约 y=1090；不得复用旧 A4 高分辨率的坐标或字号。

DOM 截图方案无法可靠嵌入 TTC 字体、处理多图层变换或保证像素级导出，因此不采用。

### 增加独立页面而非替换现有工作区

保留 `A4LayoutPage` 及其 Pinia 状态。新增豆卡页面和独立 store；原页面的入口按钮导航至豆卡页面，豆卡页面提供返回九宫格工具的按钮。两个页面不共享草稿状态、生成结果或上传图片。

在同一页切换工作区会让旧图片、裁剪状态与新插图图层相互污染，因此不采用。

### 使用 Express 管理 JSON 豆子资料库

新增 Express 服务提供 `GET /api/beans`、`POST /api/beans`、`PUT /api/beans/:id` 与 `DELETE /api/beans/:id`。服务端负责读取、校验和写入 `src/public/beans-data.json`；写入时先写入同目录临时文件，再以原子重命名替换目标，避免中断造成 JSON 损坏。每个豆子项目使用稳定 id。

Vite 开发服务器将 `/api` 代理到 Express。生产环境由 Express 先提供 API，再托管 Vite 构建产物。浏览器不直接对项目文件执行写入。

直接从浏览器写静态 JSON 不受浏览器安全模型支持；仅使用 localStorage/IndexedDB 则无法满足写回项目文件和跨设备共享的目标，因此不采用。

### 文本字段和图层状态分离

Pinia 状态分为 `cardData`（豆名、品种批次、海拔、处理法、烘焙度、风味、店名）和 `illustrations`。每张插图保存稳定 id、原始文件/解码资源、归一化中心点、缩放、旋转（首版固定为 0）与 zIndex。切换模板保留字段和插图内容；画布按当前模板重新布局文字。

这比为每套模板复制完整编辑数据更利于保持用户输入，也给将来增加模板留下空间。

### 直接操控单一选中图层

画布通过指针事件命中最上层插图；拖动改变位置，选中框上的缩放控制点改变等比缩放。图层面板提供上移、下移、删除并同步键盘可访问操作。图片可超出可视画布时裁切，不限制必须覆盖某个区域，因为插图是装饰元素。

采用自建轻量画布交互而非新增编辑器依赖，原因是需求仅包括二维平移、等比缩放与排序，且必须共用 Canvas 渲染坐标。

### 内置并等待字体加载

通过 `@font-face` 从项目资源加载 `Libian.ttc`；在首次渲染/导出前等待 `document.fonts.load` 成功。若字体不能加载，系统保留编辑内容、禁用导出并给出明确错误，不以系统替代字体静默导出。

### 导出尺寸

正方形导出为 1600×1600 px；竖版豆卡导出为 827×1169 px，与既有 2480×3508 九宫格的单元格尺寸一致。两者保持参考图的版面规则，使用源图片而非预览位图绘制；既有九宫格工具仍单独维持 2480×3508 px 输出。

## Risks / Trade-offs

- [34 MB TTC 首次加载慢] → 仅在豆卡工作区按需加载，展示加载状态并缓存已加载字体。
- [浏览器 Canvas 对某些 TTC 的支持差异] → 使用 Font Loading API 检测可用性，无法加载时阻止导出而非产生错误字体。
- [多张大图占用内存] → 限制单文件大小、及时释放被删除图层的对象 URL，并在卸载时清理资源。
- [“严格复刻”受参考图内容变化影响] → 将坐标、颜色和字号集中在模板定义中，并以两张参考图导出的截图测试作为回归基准。
- [多请求同时写 JSON 可能丢失更新] → 服务端在进程内串行化写入，且使用原子替换。
- [未认证 API 暴露到公网] → 首版限制为受信任的内部部署；公开部署前必须增加身份验证与授权。

## Migration Plan

1. 保留现有九宫格入口和工作区，添加指向新增豆卡页面的导航。
2. 添加 Express、API 和 JSON 数据文件，再新建独立的豆卡状态、页面和图层渲染，复用通用的本地图片解码及 Canvas 清理工具。
3. 以 API 读写、九宫格原有回归用例以及正方形、A4、含多插图和无插图的豆卡截图/导出测试验证两项功能。
4. 若出现回归，可移除新增页面和入口；现有九宫格代码与本地会话数据无需迁移。
